# Architecture

How CellCounter is built, the rules that keep it fast and correct, and how to change it ("Changing the app"). Features and commands are in the [README](../README.md); the chambers, formulas and rounding are in [CALCULATIONS.md](CALCULATIONS.md).

## Overview

A single-screen Expo SDK 57 / React Native 0.86 app for Android, iOS and web. It has no navigation, no backend and no state library. The `App` component holds the state as `useState`. Only the audio players, the tap volume and the haptics flag live at module level, so the tap path can use them without going through React.

| Path | Role |
| ---- | ---- |
| [index.ts](../index.ts) | Registers `App` with Expo |
| [App.tsx](../App.tsx) | Everything else: model, themes, audio/haptics, state, UI, styles |
| [calc.ts](../calc.ts) | The calculation: `CHAMBERS`, the dilution parser, `computeStats` and the number formatters. No React or React Native imports |
| [scripts/check-calc.mjs](../scripts/check-calc.mjs) | Checks `calc.ts` against CALCULATIONS.md (`npm run check:calc`) |
| [fonts.ts](../fonts.ts) / [fonts.android.ts](../fonts.android.ts) | Fonts loaded at runtime, picked per platform by Metro. Android's is empty |
| [app.json](../app.json) | Font embedding, Android permissions, splash, web `baseUrl`, React Compiler |
| [public/index.html](../public/index.html) | Web page template: Expo's default plus the theme applied before first paint |
| [.github/workflows/pages.yml](../.github/workflows/pages.yml) | Calculation check and web build, deployed to GitHub Pages on every push to `main` |
| [.github/workflows/privacy.yml](../.github/workflows/privacy.yml) | The privacy check, on pull requests |
| [CLAUDE.md](../CLAUDE.md) | Rules for AI agents. [AGENTS.md](../AGENTS.md) points to it |

`android/` and `ios/` are generated by `expo run:*` and git-ignored, so native settings go in `app.json`.

`App.tsx` reads top to bottom: model (`Square`), haptics and audio, platform helpers (`noPressDelay`, `confirmDestructive`), options and the theme (`LAYOUTS`, `THEMES`, `FONTS`), the storage keys, `App` with its five modals, the web helpers (`setupWebViewport`, `applyWebTheme`), the components, and `makeStyles`. Every name in this document is an identifier in the code, so search for the name.

## Data model

```ts
type Square = { events: CounterKey[]; touched: boolean; live: number; dead: number };
```

- `events` is the ordered tap log. Undo pops the last entry and decrements the counter it names.
- `live` / `dead` are running totals of `events`, so nothing rescans the log.
- `touched` is set by the first tap and cleared only by a reset. A square counted back down to zero stays in the mean; an untouched one doesn't.

Keep the fields in sync. `add`, `undo` and `resetSquare` change the current square through `update(fn)`. `addSquare` appends an empty square and `resetAll` replaces the list.

## Calculation

[CALCULATIONS.md](CALCULATIONS.md) is the reference for the chambers, the formulas, the dilution rules and the rounding. This is how `calc.ts` implements it.

- **Geometry, not factors.** A `CHAMBERS` entry holds the counted unit's `width`, `height` and `depth` in whole µm and its name (`unit`). `chamberGeometry` derives the volume and the factor from them, and the Data modal, the Info modal and the copied summary show the same values.
- **Two views of it.** The Data modal (bottom bar) lists the current numbers as `DataRow`s in three groups (inputs, mean per square, results), with no prose and no formulas. The Info modal (header) is the short form of CALCULATIONS.md: the counted unit of every chamber, mapped from `CHAMBERS`, then the formulas, the counting rules and the precision as fixed text. Keep it to a few lines per group; the detail belongs in CALCULATIONS.md.
- **Exact fractions.** `computeStats` returns the means, concentrations and viability as `Frac` (a `BigInt` numerator and denominator), over touched squares only, or `null` when there is no result. The dilution enters as the fraction `parseDilution` reads from the typed text, which stays in state as text. No floating point is involved, so there is nothing to compensate for.
- **Rounded once.** `formatSci` and `formatFixed` round a `Frac` to what is shown, halves up, and return `–` for `null`. Never round a value and compute with it afterwards.
- **In `App`.** `stats` is `computeStats` behind a `useMemo`, and `adjustDilution` calls `stepDilution`. Keep `BigInt` arithmetic in `calc.ts`: `App` only passes `Frac` values to the formatters.
- **No `**` on `BigInt`.** Babel's exponentiation transform compiles it to `Math.pow`, which throws on `BigInt`. Use `pow10`.

## State and persistence

| `App` state | Saved |
| ----------- | ----- |
| `squares`, `idx` | No |
| `dilution`, `chamber`, `layout`, `inverted`, `themeChoice`, `volume`, `muted`, `haptics` | Yes |
| Modal flags, `copied`, `zoneSize`, `settingsLoaded` | No |

Settings are one JSON object in AsyncStorage (localStorage on web) under `SETTINGS_KEY`. `themeChoice` is saved there as `themeMode`; on web it is read from the shared theme key instead (see "Theming").

- **Load:** once, on mount. Each field is applied only if it has the expected type or value (`volume` is clamped to 0–1), so bad fields keep their defaults. `settingsLoaded` becomes true either way.
- **Save:** after loading, changes are written 300 ms after the last one, so a slider drag is one write. A pending write is flushed as soon as `AppState` leaves `active` (on web: the tab is hidden). The `savedJson` ref skips writing JSON that matches what was last read or written.

To add a setting: add the state, validate it in the load effect, and add it to the save effect's JSON and dependency list.

## Counting path

Tap latency is the main performance requirement. A tap (a `CountZone` or diagonal-zone `onPressIn`, or an arrow key on web) calls `add(k)`. It fires `hapticLight()` and `playTap(k)` first, then `update`. Memoisation limits child re-renders to the tapped `CountZone` and the active `SquareChip`.

- **`onPressIn`, not `onPress`:** the count doesn't wait for the finger to lift, and Android's system click sound (played for `onPress`) doesn't cover the tap sounds. Screen readers trigger `onPress`, which zones don't have, so each zone also handles an accessibility action. Keep it.
- **`noPressDelay`:** without `onPress`, react-native-web delays `onPressIn` by 50 ms and drops taps released sooner, unless `delayPressIn` is 0.
- **Audio:** two players, created once by `initAudio` in an effect (on Android each constructor blocks the JS thread, which would delay the first frame). Each tap rewinds and plays one; `seekTo(0)` isn't awaited, because seek and play run in order on the same native queue.
- **Haptics:** `performAndroidHapticsAsync` on Android (system click effects, which follow the phone's touch-feedback setting), `impactAsync` elsewhere. The `hapticsEnabled` flag is synced from state in an effect. The toggle also sets it directly, so its own feedback matches the new setting.
- **Cost:** one pass over `squares` and one copy of the square's event log per tap. At realistic sizes that's negligible.

### Layouts

| Key | Name | Built from |
| --- | ---- | ---------- |
| `A` | Vertical | Two `CountZone`s side by side |
| `B` | Horizontal | Two `CountZone`s stacked |
| `E` | Diagonal | One `Pressable` over an SVG of two triangles |

`slot1` is the left / top / top-left position and `slot2` the other; "Switch positions" swaps live and dead. A diagonal tap at (x, y) counts for `slot1` when `x / width + y / height < 1`. Its labels are `pointerEvents="none"` because `locationX/Y` are relative to the view touched. On web, ← / ↑ count `slot1` and → / ↓ count `slot2`. `ZoneReadout` shows those keys as a faint `keyHint` in each zone when `KEY_HINTS` is set: on web, and only where the main pointer is a mouse or trackpad, so phones and tablets don't get a hint for keys they lack.

## Theming

The app wears the clamk-tools visual identity, the one the hub (`https://clamk-tools.github.io/`) and the other tools share, so it has a single look in light and dark and no theme picker. The identity is specified in the [brief](../LLM%20feed%20for%20visual/LLMfeed_VISUAL-IDENTITY.md), which every UI change follows; `THEMES` and `makeStyles` are its translation for this app.

```
THEMES[mode]          → Theme
Theme + scale + tight → makeStyles() → styles (passed to components as a prop)
```

- **Colours:** `THEMES` holds the identity's tokens per mode: cool neutrals (`bg`, `surface`, `text`, `muted`, `border`, `rail`), one blue `accent` for everything interactive (selection, focus ring, primary button, switches), and two marker colours. Live is the green marker and dead the coral one, so blue never carries meaning. A `Marker` has a `tint` (zone background), an `ink` (dots, large numerals), a text-safe `text` (small text; the light inks fail contrast below about 19px bold) and a `pressed` tint. Coral is also the danger colour ("Reset all").
- **Construction:** flat. 1px hairlines and the `bg` / `surface` step separate layers; radii are 7 (controls) and 9 (cards, zones, dialogs). The only shadow is on the modal sheets and the only gradient is the 6px `Rail` at the top.
- **Frame:** rail, then a header with the accent dot and the tool name on the left and the sound, settings and theme controls on the right. Groups are introduced by a `SectionLabel` (mono, uppercase, tracked, with a hairline to the right edge).
- **Mode:** `themeChoice` is `null` until the user flips the header switch, and the system setting applies until then (`userInterfaceStyle` is `automatic` in `app.json`). On web the choice is read from and written to localStorage under `clamk-tools:theme`, the key the hub and every tool share on that origin; the app's own saved `themeMode` is ignored there. `applyWebTheme` mirrors the result onto `<html>` (`data-theme`, the `--accent` variable for the focus ring, `color-scheme`). `public/index.html` does the same before first paint with an inline script and the two `bg` colours, so the page isn't white while the bundle loads; keep those colours equal to `THEMES`.
- **Sizing:** `scale` sizes the large numerals: the smaller of `min(width, 560) / 390` and `height / 800`, clamped to 0.8–1.3. `tight` (window under 700 high) shrinks the header padding and the gaps between groups so the zones keep room. Content is at most `MAX_CONTENT_WIDTH` (560) wide and centred; the rail is full width.

### Fonts

`FONTS` names Figtree in three weights (`m` 500, `sb` 600, `b` 700) for content, UI and the large numerals, and IBM Plex Mono 600 (`mono`) for labels, metadata, formulas and the dilution field. They are imported per weight so only 4 files are bundled. Changing a font means updating `fonts.ts`, the `expo-font` list in `app.json` and the names in `FONTS`.

- **Android:** the `expo-font` plugin embeds the fonts at build time, registered under their file names. `fonts.android.ts` is empty, so the first frame already has them.
- **iOS and web:** loaded at runtime. `App` shows a blank background until they load, or falls back to system fonts if loading fails (for example offline on web).

## Platform differences

| Concern | Android | iOS | Web |
| ------- | ------- | --- | --- |
| Fonts | Embedded at build | Loaded at runtime | Loaded at runtime |
| Haptics | `performAndroidHapticsAsync` | `impactAsync` | `impactAsync` |
| Confirm dialog | `Alert.alert` | `Alert.alert` | `window.confirm`, via `confirmDestructive` (`Alert.alert` is a no-op) |
| Share | Share sheet | Share sheet | `navigator.share`; copies instead on any error except the user cancelling |
| Counting keys | – | – | Arrow keys, off while a modal is open or an input has focus |
| Theme choice | Saved with the settings | Saved with the settings | Shared `clamk-tools:theme` key |
| Hover and focus | – | – | Pressables read `hovered` (`PressState`); the focus ring and the 120 ms border transition are CSS from `setupWebViewport`, dropped for `prefers-reduced-motion` |
| Viewport | – | – | `setupWebViewport`: `100dvh`, no double-tap zoom, no text selection outside inputs |

`app.json` blocks unused Android permissions (`RECORD_AUDIO`, external storage) and disables backup. It deliberately keeps `INTERNET` and `SYSTEM_ALERT_WINDOW`, which development builds need to reach Metro.

## React Compiler

Enabled in `app.json` and currently compiles every component. The manual `memo` / `useMemo` / `useCallback` calls stay, so performance doesn't depend on it. A component that breaks the compiler's rules is skipped silently, so keep render pure:

- No module-variable writes during render (use an effect, like `hapticsEnabled`).
- No `ref.current` reads or writes during render; only in handlers and effects.
- No ref-reading closures passed to functions called during render. `PanResponder.create` counts, which is why `VolumeSlider` doesn't use it.

To list what compiles:

```bash
node -e "require('@babel/core').transformFileSync('App.tsx',{babelrc:false,configFile:false,presets:[['@babel/preset-typescript',{isTSX:true,allExtensions:true}]],plugins:[['babel-plugin-react-compiler',{logger:{logEvent:(f,e)=>/^Compile(Success|Error)$/.test(e.kind)&&console.log(e.kind,e.fnName??'line '+e.fnLoc?.start.line)}}]]})"
```

## Web deploy

Every push to `main` first passes the `privacy-guard` job (`.githooks/check-privacy.sh` on the commits the push adds and on every tracked file; nothing is built or deployed if it fails), then runs `npm run check:calc` and `npx expo export --platform web` and publishes `dist/` to GitHub Pages. `experiments.baseUrl` in `app.json` (`/CellCounter`) must match the repo name (case-sensitive) and the Pages path, `https://clamk-tools.github.io/CellCounter/`. Pull requests run the same privacy check through `privacy.yml`.

## Changing the app

The app is expected to keep evolving, mostly through AI agents. Nothing here is off limits: structure, libraries, identifiers and formulas can all change when that makes the app better. This section says what each kind of change touches, which identifiers have effects outside the code, how to check the result, and what the code doesn't do yet.

### Recipes

| Change | Touch |
| ------ | ----- |
| Chamber | An entry in `CHAMBERS` with the unit that is counted as one square: its `unit` name and its `width`, `height` and `depth` in whole µm, from the maker's specification. Add it to "The chambers" in CALCULATIONS.md with its source, and to the geometry checks in `scripts/check-calc.mjs`. The factor, the picker, load validation, the Data and Info modals and the summary follow |
| Formula, rounding or dilution rule | `calc.ts`, CALCULATIONS.md and `scripts/check-calc.mjs` together, then the text of the Data and Info modals and `summaryText` in `App` |
| Layout | `LayoutKey`, `LAYOUTS`, a render branch in `App` and a case in `LayoutIcon`. Its zones follow "Counting path" and place `slot1` / `slot2`. The settings tiles and load validation follow |
| Setting | "State and persistence" |
| Modal | Its open flag, `modalOpen` (which turns the web counting keys off), and the backdrop / sheet pair of `Pressable`s with `onRequestClose` |
| Counter beyond live and dead | `CounterKey`, `emptySquare`, a player and sound in `initAudio`, a `Marker` in `Theme`, `computeStats`, `summaryText`, the Results and Data views. `slot1` / `slot2`, the three layouts, the web keys and the diagonal zone's accessibility handler all assume two counters |
| Colour | A field in `Theme` and a value in both `THEMES` modes, used through `makeStyles` or the `theme` prop, never as a literal in a component. `bg` is repeated in `public/index.html` and as the splash background in `app.json` |
| Style or size | `makeStyles`. Components get `styles` as a prop; sizes that follow the screen use `scale` or `tight` |
| Icon | A path in `ICONS` on a 24-unit grid; `Icon` draws it with a 2px round stroke |
| Font or weight | "Fonts" |
| Component | Define it below `App`, pass it `styles` (and `theme` for colours), add it to "Components", and check that it compiles ("React Compiler") |
| Dependency | `npx expo install <package>`, so the version matches the SDK, and commit `package-lock.json` (CI runs `npm ci`). A package with native code needs its config plugin in `app.json` and a new development build |
| Expo SDK upgrade | Expo's upgrade guide, then every check below on Android and web. The SDK and React Native versions are named in "Overview" and `CLAUDE.md` |

### Identifiers with outside effects

These are stored on users' devices or shared with other systems. Change one whenever the change calls for it; handle its effect in the same change and name it in the summary.

| Identifier | Effect of changing it, and what to do |
| ---------- | ------------------------------------- |
| `SETTINGS_KEY` and the field names of the saved JSON | A renamed key or field silently resets that setting for every user. Keep reading the old form in the load effect |
| The keys in `CHAMBERS` and `LAYOUTS` | They are the saved values of `chamber` and `layout`; a renamed key fails load validation and falls back to the default. Map the old key on load |
| `SHARED_THEME_KEY` and its values `light` / `dark` | The hub and the other tools read the same key, so a change here alone stops the theme being shared. It is repeated in `public/index.html` |
| The Android `package` in `app.json` | Android treats another package as another app: installed copies don't update and their settings stay behind |
| `experiments.baseUrl` in `app.json` | It has to match the repo name ("Web deploy") |
| The formulas, the chamber dimensions and the rounding | They are the app's result: a change gives users different numbers for the same counts. Change `calc.ts`, CALCULATIONS.md, `scripts/check-calc.mjs` and the Data and Info modals together, and say in the summary which results move and by how much |

### Checking a change

There is no test framework and no linter, so these are the checks:

1. `npx tsc --noEmit` passes.
2. `npm run check:calc` passes. It runs `calc.ts` under Node (22.18 or later, which runs TypeScript files directly) and asserts the chamber geometry, the worked example, the dilution rules and the rounding in CALCULATIONS.md. CI runs it before the web build, so a wrong number isn't deployed. `calc.ts` has to stay free of imports and of syntax Node can't strip (no `enum`, no `namespace`).
3. The listing in "React Compiler" reports `CompileSuccess` for every component.
4. `npx expo export --platform web` succeeds, for a change to dependencies, `app.json`, `public/` or assets. It is what CI builds, and it writes to the git-ignored `dist/`.
5. The behaviour works in the running app. `npm run web` is the quickest and covers everything except haptics, the native share sheet, the native confirm dialog and Android's embedded fonts, which need `npm run android`.

After a change to the calculation or to what the Results and Data views show, go through the "Worked example" steps of CALCULATIONS.md in the running app: the check script covers `calc.ts`, not how `App` wires it.

After a change to counting, layout or state, also check: both zones count on touch-down in each layout, and with ← ↑ / → ↓ on web; "Switch positions" swaps the zones and the keys; Undo, Reset and Reset all; dilution `2,5` is accepted, and an empty or zero dilution shows `–`; settings survive a reload and counts don't; light and dark; a window under 700 high.

### Current limits

What the code does not do today. None of it is a requirement: lift a limit when a change is better for it.

- **Tests:** only `scripts/check-calc.mjs`, for the calculation. Nothing tests the components, the tap path or persistence.
- **Uncertainty:** the results carry no error estimate, whatever the number of cells counted ("What the result does not include" in CALCULATIONS.md).
- **Counts:** `squares` and `idx` live only in React state, so they are lost when the app closes or the page reloads.
- **One file:** `App.tsx` holds nearly everything but the calculation. Split it, or add a state, navigation or test library, when that makes the app easier to change. A split keeps `styles` built once in `App` and passed down (the memoised `CountZone` and `SquareChip` depend on its identity staying stable across taps), runs the compiler listing on every file that has components, and updates the file tables here and in the README.
- **iOS:** `app.json` has an Android `package` and a web `baseUrl` but no iOS `bundleIdentifier`.
- **Text:** the UI strings are English literals in the JSX.
